# 업무 주기 (Work Cycle) & 검증 게이트

모든 구현 작업은 아래 주기를 따른다. 단계를 건너뛰거나 순서를 바꾸지 않는다.
E2E 검증의 상세 방법은 `skills/e2e-playwright/SKILL.md`를 따른다.

---

## 1. 작업 단위 주기 (Task Cycle) — 기능 1건마다 반복

작업 단위 = **API Route 1개 + 연결된 화면 1개** 또는 그에 준하는 크기(예: "플랫폼 설정 저장 API + 저장 폼"). 이보다 크면 쪼갠다.

| # | 단계 | 해야 할 일 | 통과 기준 |
|---|---|---|---|
| ① | **착수** | PRD 해당 절 + Phase 스킬 + `harness-decisions.md` 확인. 작업 목표와 이번 작업의 완료 조건을 3줄 이내로 먼저 적는다 | 목표·완료 조건 명시 |
| ② | **구현** | 규칙(`rules/*`) 준수하여 코드 작성. 신규 로직(파서/정규화/토큰/암호화/타겟팅)은 단위 테스트를 **함께** 작성 | — |
| ③ | **정적 검증** | `npx tsc --noEmit` → `npm run lint` | 오류 0 |
| ④ | **단위 테스트** | `npm test` (vitest) | 전부 통과 |
| ⑤ | **E2E 검증 (headless)** | 영향받는 화면의 Playwright spec을 작성/갱신하고 실행: `npm run test:e2e -- <spec>` | 전부 통과. UI가 있는 작업은 E2E 없이 완료 불가 |
| ⑥ | **자가 점검** | 변경 파일의 쿼리에 `userId` 포함, 비밀값 비노출, 실제 발송 경로 차단 여부 확인 | 위반 0 |
| ⑦ | **보고** | 아래 「보고 형식」으로 결과 보고 | — |

### 실패 처리
- ③~⑤ 실패 시 원인 수정 후 **③부터 다시** 실행한다.
- 같은 실패로 **수정 시도 3회**가 넘으면 멈추고, 실패 로그·원인 가설·시도한 내용을 보고한 뒤 사용자 판단을 받는다.
- 테스트를 통과시키려고 테스트를 삭제·`skip`·약화(단언 제거, timeout만 늘리기)하지 않는다. 테스트가 틀렸다고 판단되면 근거를 보고한다.

## 2. Phase 주기 (Phase Cycle) — Phase 1~5 각각

```
Phase 착수 ─▶ 작업 단위 주기 × N ─▶ Phase 게이트 ─▶ 사용자 승인 ─▶ 다음 Phase
```

### Phase 게이트 (모두 통과해야 Phase 완료)
1. `npx tsc --noEmit` / `npm run lint` / `npm test` 전부 통과
2. **E2E 전체 스위트 headless 실행** `npm run test:e2e` — 이전 Phase spec 포함(회귀 확인), 전부 통과
3. 해당 Phase 스킬 「완료 조건」 체크리스트 전 항목 충족
4. 규칙 준수 검토 (Claude Code: `harness-reviewer` 서브에이전트 / 그 외: `harness-reviewer` 점검 항목을 직접 수행) — 🔴 항목 0건
5. Phase 결과 보고 → **사용자 승인 후** 다음 Phase 착수

---

## 3. 주기적 점검 (Recurring)

| 시점 | 수행 |
|---|---|
| 작업 단위 완료 시마다 | 영향 spec E2E (⑤) |
| 작업 단위 **3건마다** | E2E 전체 스위트 1회 (회귀 조기 발견) |
| 스키마/모델 변경 시 | E2E 전체 스위트 + 시드 재적재 확인 (`npm run seed`) |
| 의존성 추가·업그레이드 시 | `npm run build` + E2E 전체 스위트 |
| Phase 종료 시 | Phase 게이트 (위 2절) |

## 4. 보고 형식

```
## 작업: <작업명> (Phase N)
- 변경 파일: <목록>
- 정적 검증: tsc ✅ / lint ✅
- 단위 테스트: ✅ N passed
- E2E(headless): ✅ N passed  (spec: e2e/xxx.spec.ts)   ← 실패 시 ❌ + 실패 테스트명 + 원인
- 자가 점검: 테넌트 격리 ✅ / 비밀값 ✅ / 실제 발송 차단 ✅
- 남은 이슈 / 다음 작업: <...>
```
검증을 실행하지 못한 항목은 ✅로 쓰지 말고 `⏭ 미실행 (사유)`로 표기한다.
